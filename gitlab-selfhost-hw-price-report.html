相对初版的更正： 初版「1 应用 + 1 Runner（40–64 核 / 256G，concurrent≈48）」只够尖峰不崩， 对不齐 GitHub 标准托管 runner 约 2 vCPU / job 的同速。 父仓近 14 日尖峰同时 job ≥43、跨 run 同时可达约 25 场，且几乎全是 pull_request 触发。 本版改为 1 应用 + 2 台 Runner，合计约 80–128 核级吞吐 + 512G 内存池。
约 ¥2.5万 – ¥4.0万
推荐采购带（1×应用 + 2×Runner + UPS/导轨）。内存已含在机头 SKU；盘另计。

0. 用量依据（并发 PR）

观测 / 假设数值含义
日均 workflow runs~240父仓近 14 日
触发类型几乎全是 PR并发 PR 是主负载
跨 run 同时进行日常 6–12；尖峰 ~20–25多 PR 叠跑
同时在飞 jobs≥43（抽样下界）设计余量按 60–80 槽
GitHub 标准 Linux job~2 vCPU / ~7GB同速标尺
同速所需总算力~86+ vCPU；内存池 ~170–300GB+43×2 核；再留余量

4. 结论

要扛你们这种并发 PR 尖峰，实体硬件预算按约 ¥2.5万–4.0万 准备（两台 Runner），不要再按单台 40–64 核去对齐 GitHub 同速。

相对 GitHub private Actions ~$2k/月，这套硬件大约一个多月回本量级（视利用率与电费）。详细 BOM 见同目录 gitlab-selfhost-hw-bom.md。
